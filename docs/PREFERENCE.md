# 直接改写与后台偏好学习

生成后点击 CRT 中的句子直接编辑，再点击“提交改写”。只接受 2～800 个 Unicode 字符的单行整句。未改动、空白、超长输入不会提交。“恢复原文”取消编辑；编辑期间点赞和点踩禁用，以免把编辑内容误当作原句评价。

提交时，SQLite 事务保留原输出、保存改写与生成上下文，并创建独立偏好任务。原句标为负向、改写标为正向；不会删除原句，也不会为这次改写额外创建普通监督任务。正常投喂、点赞继续使用原监督队列。worker 交替消费两类队列，单一写入者串行更新权重；同步 LoRA 底座仍使用同一个串行控制通道。

## 实际计算

算法为 DPO + chosen SFT + replay SFT。使用原始 [DPO 论文](https://arxiv.org/abs/2305.18290) 的策略与参考模型对数概率差：

```text
DPO = softplus(-0.1 * ((logπ(chosen)-logπ(rejected))
                     -(logref(chosen)-logref(rejected))))
总损失 = DPO + 0.5 * chosen平均交叉熵 + 0.1 * 回放平均交叉熵
```

每条偏好对使用生成时不可变 checkpoint 作为参考，而不是随梯度更新参考模型。因此这是逐条在线偏好学习，不是全数据集共享一个参考模型的离线 DPO，也没有奖励模型或 PPO。生成时保存精确 prompt token、主题和参考 checkpoint。若改写保留生成开场，两答案在同一个开场后比较续文；若连开场也改了，则在同主题控制 token 后比较全文。prompt 和 padding 不参与损失，结束 token 参与。超过 context 的长句按窗口计算，后续窗口只能看到该窗口上下文，这是小模型长度限制的近似处理，不会静默丢弃尾句。

每次提交做一个 FP32 梯度步骤，全局梯度裁剪为 1，初始学习率底座 0.0005、LoRA 0.001；若混合损失未下降，会最多六次减半尝试，失败恢复权重并记为 error。回放最多四条未被点踩的可信训练种子。该检查只约束本次混合损失，不保证纯 DPO 项或中文可读性每次都改善。

## 底座、LoRA 与持久化

任务按原 sample_id 查找所属标注库；前端当前选项不会重定向已生成样本。底座改写更新完整模型；LoRA 改写只更新适配器并校验冻结底座摘要。普通投喂仍训练提交时选择的原版或角色。

`generation_contexts` 保存生成上下文，`preference_jobs` 保存原文、改写、参考快照、分词输入、状态与训练指标。原版在 `data/feedback.sqlite3`，角色在 `data/lora/<角色>.sqlite3`。checkpoint 的 `last_preference_id` 独立于普通训练 job id，支持重启恢复，避免保存权重后未确认任务导致重复训练。同一样本、同样改写重复提交不会重复更新；失败任务可重新提交相同改写来重试。历史快照须保留，参考文件缺失或配置、词表不兼容时明确失败，不拿当前权重冒充参考。

新代码启动前产生的旧样本没有完整生成上下文，不能直接用于此流程；刷新网页后重新生成即可。接口 `POST /api/correct` 接收 `{ "sample_id": "...", "text": "改好的整句" }`。响应 pending 表示已入队，不代表已经训练完成。单独点踩仍只是排除正向回放，不会执行偏好梯度。

## 验证与效果边界

MLX 本机真实验证了底座及 LoRA 改写训练、普通投喂共存、权重保存与样本归属；数值测试覆盖 PyTorch CPU 和 MLX 概率一致性、prompt/padding mask、长句尾部、纯 DPO 偏好方向、冻结参考及 LoRA 底座、重复任务恢复。CUDA 沿用 PyTorch 分支，未在 CUDA 硬件实测。

一百万参数、少量样本只能做小范围表达实验。尽量把原句改成你真正希望它输出的完整自然句，持续提供一致例子；一次更新不会立刻学会语法，过少且重复的例子可能造成记忆或重复。底座继续监督学习、角色继续投喂和改写可同时保留，迁移底座后仍需要观察角色表达。
